Add policy planning to /app/tools/msbuild_audit.py:

python3 /app/tools/msbuild_audit.py plan /app/src /app/Directory.Packages.props /app/policy/runtime-policy.json /app/out/msbuild-runtime-plan.json

The command reads the current project, package, and policy files and writes actions plus summary. Each action row has exactly path, name, action, reasons, and target, with paths relative to /app/src. Sort rows by action priority retire, update, keep, then by path. Retire projects whose target framework is in retire_frameworks. For non-test projects, update when target framework, nullable, runtime identifiers, or referenced package versions do not meet policy. For non-retired test projects, use allowed_test_frameworks and an empty target RID array. If a test project's target framework is not in allowed_test_frameworks, include the phrase "allowed list" in one of its reasons. Apply minimum_packages only to packages already referenced by the project, and make reason strings name the failing area such as target framework, runtime identifiers, nullable, or the package name.

Support runtime_profiles and path_profile_overrides. A project selects RuntimeProfile first, otherwise the longest matching relative path prefix. Profile objects use the same policy key names as the base policy: required_framework, required_nullable, required_rids, and minimum_packages. For example, a runtime_profiles entry named linux-worker may set required_framework to net8.0, required_nullable to enable, required_rids to ["linux-x64"], and minimum_packages to {"Serilog": "3.1.1"}. Profile values override framework, nullable, RIDs, and package minimums; profile package minimums merge with base minimums. Reasons caused by a profile must include runtime profile <name>. target contains target_framework, nullable, and runtime_identifiers. summary contains retire, update, and keep counts.
