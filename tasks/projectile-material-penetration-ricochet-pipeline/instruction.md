The projectile ballistics tool under /app simulates material-stack penetration, ricochet, and multi-tick batch hit export for game combat traces. Fixture stacks, material catalogs, and batch scenarios are listed in /app/fixtures/catalog.json and /app/fixtures/seeds.json.

Complete the Rust packages under /app/crates/ballcore in place so the two-step shot pipeline (ballctl integrate-shot then ballctl export-shot) and ballctl simulate-batch write exports matching /app/docs/export-schema.md, /app/docs/export-shot-contract.md, and /app/docs/physics-reference.md. Preserve existing exported function names, type signatures, and struct field names across ballcore modules — partial verification rebuilds swap reference sources into individual modules and require surviving code to compile against the existing API.

Integration writes /app/state/shot-snapshot.json per /app/docs/staging-snapshot.md with replay_seq per /app/docs/replay-epoch.md; export reads that snapshot and emits shot JSON including trace_digest from /app/docs/export-shot-contract.md. Material binding, layer traversal, penetration debits, energy falloff timing, ricochet reflection, batch tick ordering, and replay sequencing are defined in /app/docs/material-binding.md, /app/docs/penetration-contract.md, /app/docs/ricochet-contract.md, and /app/docs/batch-contract.md. Use /app/README.md for CLI flags.

Rust and cargo are on PATH at /usr/local/cargo/bin; ballctl is installed at /usr/local/bin/ballctl. Do not run apt-get or install a toolchain. Rebuild only with cargo build --release --locked -p ballctl from /app after editing sources. Do not edit /app/docs/, /app/fixtures/, or hardcode export JSON. Repeated runs on the same inputs must yield byte-identical export files when /app/state/ is reset between runs.
