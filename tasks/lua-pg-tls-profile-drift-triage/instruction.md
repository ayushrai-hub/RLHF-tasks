Payments ingress TLS bundles drifted from the PostgreSQL certificate inventory after an emergency CA rollover. Checked-in YAML and TOML under `/app/environment/config/bundles/` disagree with live certificate rows: fingerprints no longer match, stale trust anchors still look enabled, service-to-CA bindings point at the wrong client CA, and revoked or expired material is leaking into the digest.

Back-to-back runs of `/app/bin/ingressctl tls-reconcile` emit incomplete drift rows and an inventory digest that does not match what the database actually contains. Repair the Lua pipeline sources under `/app/environment` so the command queries PostgreSQL, reconciles both bundles, and regenerates `/app/out/reconcile_report.json`. The report carries api_version, rollover_epoch, inventory_digest, trust_anchors, service_bindings, and drift_rows; trust anchor rows include anchor_id and reason; service bindings include client_ca and fingerprint. Report shape, digest rules, grace handling, bundle precedence, and trust-anchor disable logic are defined in `/app/environment/docs/reconcile_contract.md` and `/app/environment/manual/rollover_runbook.md` (later amendments supersede earlier tables). Invocation and database seed steps are in `/app/environment/docs/operators.md`.

Hand-written JSON is insufficient; the verifier reruns database seed and restart per operators.md, then reruns the pipeline. Independent verification may import Python yaml, tomllib, and jsonschema modules as documented in reconcile_contract.md.
