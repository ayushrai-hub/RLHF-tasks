We're building the storage layer for a small embedded key-value store: an on-disk B+tree index that other tools will mmap and read, so its bytes have to be reproducible down to the last padding byte. The whole format and every behaviour are pinned in `/app/docs/bptree-spec.md` and that file is the contract, not a suggestion. There's a C++17 scaffold under `/app` (`Makefile`, `include/`, `src/`) with the moving parts stubbed out; keep it standard library only and make sure `cd /app && make` still produces `/app/bin/bpt`.

This milestone is build, serialize and read-back. `bpt build <ops-file> --out <idx>` starts from an empty tree, applies the operation file in order, and writes the index at `<idx>`; two different runs on the same operations must yield byte-identical files. `bpt get <idx> <key>` prints the stored value for a key or the line `NOT-FOUND`. `bpt dump <idx>` prints the canonical textual view of the tree the spec describes. The splits are where this gets fiddly — leaves and internal nodes divide differently and promote different keys — and the page numbering that lands in the file is not the order in which nodes were created, so read section 3 carefully.

There's a large pile of operation files under `/app/data` covering the split boundaries and plenty of ordinary cases; get the serialized bytes, the lookups and the dumps all matching the spec before moving on, because deletion and range scans build directly on this format next.
