Difficulty Explanation
----------------------
This task is hard because fixing the sampler requires reconciling four separate concerns that are easy to get almost-right: live PostgreSQL access (correct `u`/`v`/`split` columns via `db.js`), train-only subgraph traversal for BFS distance, the exact hard-negative distance window of 2–3 hops, and seeded deterministic selection where different seeds must yield genuinely different unordered pair sets. The broken implementation looks plausible—it reads a snapshot and returns JSON with the right shape—so agents must read the spec docs and tests' implied invariants rather than patching the obvious `Math.random` call alone.

Solution Explanation
--------------------
Replace `src/lib/sampler.js` so it connects through `db.js`, loads node ids and all edges from Postgres, builds an adjacency list from train edges only, enumerates non-edge pairs at BFS distance 2–3, excludes every split's edges from the candidate pool, shuffles candidates with a seed-driven PRNG, takes the first `k` pairs, and labels `source` as `"postgres"`. Run the existing CLI to write `/app/output/negatives.json` and the static audit to produce `/app/output/audit.json` with `status: "ok"`.

Verification Explanation
------------------------
Pytest brings up PostgreSQL, recomputes train/val/test edge sets and train-subgraph distances from the live database, and invokes the sampler CLI with multiple seeds and batch sizes. Tests assert JSON schema, `source="postgres"`, no split leakage, distance ∈ [2, 3], uniqueness, determinism for repeated seeds, different unordered sets across seeds, and a clean static audit. Canonical `/app/output/negatives.json` and `audit.json` from the agent run are checked first.
