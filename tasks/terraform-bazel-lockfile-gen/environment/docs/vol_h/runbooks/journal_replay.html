Journal replay

Runtime state lives under /app/environment/.runtime/journal/. Use a single closure.json file with a slots map (no per-entry subdirectories), plus epoch.json per-entry apply counters and replay_gen.json global apply generation.

Reuse a cached slot only when slots[ROOT_ENTRY].seed_digest matches the active root fixture fingerprint. The fingerprint is sorted comma-separated seeds, a pipe, then storage_class from the active root fixture JSON. A stale digest, phantom nodes injected into the active slot, or a slot clobbered from another entry must force a fresh closure walk for that entry.

Each slot stores nodes and a pins map of resolved versions. Long rotations across entries must preserve prior slots so returning to a matrix entry restores its pins rather than reusing another entry's closure.

Increment the active entry counter in epoch.json and the global replay_gen.json counter on every successful apply, including replays where the cross-artifact link digest is unchanged.

The replay-chain witness uses prefix linkage: the first line carries prefix genesis; each later line's prefix is the SHA-256 hex digest of the prior line's raw UTF-8 bytes (no trailing newline in the hash input). Hydration must reject chains whose prefix linkage does not validate end-to-end and must reject replay-chain files containing malformed non-JSON records, not just records with bad prefix linkage. Valid applies append new lines while linkage holds. When linkage breaks or a malformed record is present, truncate the witness to a single fresh genesis-linked line for the next successful apply rather than appending past corruption.
