Build a Go program at /app/spf-trace that evaluates each envelope in /app/data/messages.jsonl against the offline DNS snapshot at /app/data/dns.json under the budgets in /app/data/policy.json, and writes /app/output/verdicts.ndjson plus /app/output/summary.json. The full contract for record parsing, TXT rrset joining, mechanism semantics, qualifier grammar, macro expansion including custom delimiter tails, IPv4-mapped IPv6 family handling, the exact mechanism-field grammar for both direct and redirect-resolved verdicts, the two counters, and the two loop guards lives in /app/docs/sender_macros.md and /app/docs/budget_limits.md. The chain_digest field in summary.json is defined in /app/docs/chain_digest.md. Ship all source under /app/spf where a go.mod already exists; the module builds offline with GOPROXY=off so stick to the Go standard library.

The verdicts file has one JSON object per input message in input order with fields id, result, mechanism, domain, lookups, void_lookups, and trace as specified. The summary file is pretty-printed with two-space indent and a trailing newline, keys ordered total, counts, chain_digest; counts is keyed by every one of pass, fail, softfail, neutral, none, permerror, temperror even when zero.

A small self-check pair at /app/data/sample_in.jsonl and /app/data/sample_out.ndjson lets you confirm the base pipeline on simple messages before the full run. The messages fixture, DNS snapshot, policy, sample pair, and docs are read-only inputs.
