# chain-digest

The summary.json object emitted by the program carries a third top-level field named chain_digest that binds all of the verdict lines together into a single fingerprint. Its value is a lowercase hexadecimal string 64 characters long, computed as follows.

Start with an accumulator state that is the 32-byte all-zero SHA-256 output. Then, in verdict-file order (which is input-message order), for every JSON object line that was written to verdicts.ndjson, compute a per-line hash as follows: take the canonical eight-character message id (the id field, exactly as it was written on that verdict line), then a single ASCII pipe character "|", then the result field (one of pass, fail, softfail, neutral, none, permerror, temperror — exactly as written), then another "|", then the mechanism field (the exact string that was written, including the empty string for none/permerror/temperror/neutral-fallthrough), then another "|", then the domain field, then another "|", then the lookups counter formatted as its shortest decimal representation, then another "|", then the void_lookups counter formatted the same way. Encode this six-part string as UTF-8. The per-line digest is the SHA-256 of the concatenation of the CURRENT accumulator (32 bytes) and this UTF-8-encoded six-part string. The new accumulator is that per-line digest. When every verdict line has been folded in, the final accumulator, rendered as its lowercase 64-character hexadecimal, is chain_digest.

For total=0 (no verdict lines), chain_digest is the hex encoding of the initial all-zero accumulator, i.e. 64 zero characters. For any other total, one wrong verdict line — even one whose result was correct but whose mechanism string had an unexpanded macro replaced by its expanded form, or whose lookups counter was off by one due to missing memoization — cascades through every subsequent per-line digest and produces a chain_digest that differs from the expected value in essentially every bit. Partial correctness on individual lines is invisible on chain_digest; individual line assertions are what a graded test uses to score them.

The trace field is deliberately NOT included in the chain_digest input. Trace is a debugging aid whose exact recursion order can drift across otherwise-correct implementations; the six fields listed above are the load-bearing verdict identity.

Neither the JSON encoding of the verdicts.ndjson line nor any whitespace inside a line enters the chain_digest — the digest is computed strictly from the six raw field values in the order id, result, mechanism, domain, lookups, void_lookups. The delimiter is always the single ASCII pipe character; there is no escape mechanism because no field value is allowed to contain a pipe (mechanism strings never contain "|"; domains and results by definition never do; counters are decimal integers).
