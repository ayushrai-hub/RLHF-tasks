### Milestone 3: ffmpeg remux artifacts + six-rule HLS validator chain

Build on the working M2 surface. Implement `recover remux <playlist_id>`, `recover validate <rule> [<playlist_id>]`, and `recover audit list`. Internet access is still disabled; the verifier exercises SQL assertions against `artifacts`, `audit_log`, and `playlists` to confirm correctness.

`recover remux <playlist_id>` concat-muxes the plaintext segments of one playlist into `/app/data/artifacts/<playlist_id>.mp4` using ffmpeg. Exact argv: `ffmpeg -nostdin -y -hide_banner -loglevel error -fflags +bitexact -f concat -safe 0 -i <concat_list> -flags +bitexact -map_metadata -1 -c copy <out_mp4>`. Input options precede `-i`; output options follow it. The concat list is written to a temp file inside `/tmp` listing one `file '<absolute_path>'` line per segment in `segment_index` order. After ffmpeg returns 0 SHA-256 the MP4 bytes (lowercase hex), insert exactly one row into `artifacts` with `(playlist_id, mp4_path, sha256, created_ms)` and append an `audit_log` row with `action=remux`, `target=<playlist_id>`, `decision=allow`. Success body: `{"artifact_id":N,"playlist_id":"<id>","sha256":"<hex>","status":"ok"}`. Missing segments raise `{"error":"missing_segments",...}` with exit 1 and a `decision=deny` audit row.

`recover validate <rule> [<playlist_id>]` implements the six rules in `/app/docs/validator-rules.md`: `byte_range_parse`, `key_uri_format`, `iv_pinning`, `ext_x_key_scope`, `segment_encryption_rotation`, `codec_private_integrity`. The optional second positional argument `<playlist_id>` selects which playlist row the chain update targets; when omitted, the implementation defaults to `cam001`. Each rule returns a boolean computed strictly from the manifests under the configured manifests directory (default `/app/data/hls_export/manifests/`, overridable via the `HLS_MANIFESTS_DIR` environment variable), the segment files under the configured segments directory (default `/app/data/hls_export/segments/`, overridable via the `HLS_SEGMENTS_DIR` environment variable), and the `wrapped_keys` rows; do not consult ad-hoc heuristics. Both env-var overrides MUST be honoured so the verifier can inject per-case manifests from a scratch directory under `/tmp`. The rule outcome MUST be folded into the named playlist's `audit_validator_sha256` column per `/app/docs/audit-chain.md`: the new value is the lowercase-hex SHA-256 of `prev_validator_sha256|rule_name|('1' if valid else '0')` and the column starts as the empty string. The verifier invokes the six rules in the canonical order documented in `/app/fixtures/expected_validators.json` against `cam001` and compares the final column value byte-for-byte. Success body: `{"rule":"<name>","valid":<bool>,"validator_sha256":"<hex>"}`.

The fixture set under `/app/fixtures/validator_cases.json` lists 24 cases (two valid + two invalid per rule). The verifier exercises every case via `validate <rule> <playlist_id>` while pointing `HLS_MANIFESTS_DIR` and `HLS_SEGMENTS_DIR` at a per-case scratch tree under `/tmp` and asserts the returned `valid` boolean matches `expected_valid`. Invalid cases MUST NOT mutate the canonical playlist's `audit_validator_sha256` chain on cam001 because the verifier injects them against scratch playlists in `/tmp`. Concretely, the implementation MUST decide whether to fold the rule outcome into the persisted `audit_validator_sha256` column by comparing the absolute, normalised path of the resolved manifests directory against the canonical default `/app/data/hls_export/manifests/` (`Paths.get(manifestsDir).toAbsolutePath().normalize()` equality). If, and only if, the resolved manifests directory equals the canonical default, the implementation updates the column; otherwise the call computes the chain value purely in memory for the JSON response and leaves the column untouched. Returning the computed `validator_sha256` in the response on the scratch path is REQUIRED; persisting it is FORBIDDEN. This guard applies to every rule and every playlist id, not just `cam001`.

`recover audit list` returns `{"count":N,"entries":[{...},...]}` with every `audit_log` row in `seq` order, each entry containing `seq`, `ts_epoch_ms`, `actor`, `action`, `target`, `decision`, `prev_hash`, `entry_hash`. The verifier re-derives every `entry_hash` and asserts the chain is intact.
