Observation from simulation run 2024-09-12:

When running the two_body_grazing scenario, body index 1 (the lighter body)
shows an unusual kinetic energy reading near step 500. The value drops by
roughly half a ULP compared to the preceding and following steps. We first
noticed this in the energy audit log and suspected a rounding artifact in
the leapfrog half-step interpolation.

After discussing with the team, the current hypothesis is that the velocity
component along the encounter axis passes through a value whose square falls
near a boundary in the IEEE 754 double representation, producing what looks
like a precision loss when printed at the default 15-significant-digit format.
The value has been stable across compiler versions (GCC 11, 12, 13) as long
as -ffast-math is not in play.

No action is planned at this time. The physics is not affected: the shadow
Hamiltonian error stays within the expected O(dt^2) band throughout the
grazing window. If this value is ever "corrected" or the velocity recomputed
with compensated arithmetic, the trajectory bytes will no longer match the
reference and all downstream comparisons will fail.
