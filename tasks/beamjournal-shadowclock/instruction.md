Journal and plan files are binary streams with a 4-byte trailer that readers ignore. Multi-byte integers are little-endian.

Journal records are legacy or extended. A legacy record is `[u16 payload_len][u8 enabled][u8 scope_len][scope bytes][u8 kind][payload]`. An extended record is `[u16 record_len][u8 enabled][u8 scope_len][scope bytes][u8 255][u8 actual_kind][u8 flags][payload]`, where `record_len` includes `actual_kind`, `flags`, and payload bytes. Disabled records are parsed but do not contribute output or entries. Valid actual kinds are `0` through `5`. Records whose scope equals the requested scope contribute output; records with scope `all` contribute to every requested scope.

Extended flags are applied before the kind transform, except bit `0x04`, which repeats the kind transform once after the first transform. Bit `0x01` expands payload bytes as RLE pairs `[count][byte]`. Bit `0x02` interleaves halves by emitting `second[0], first[0], second[1], first[1]...`, with the first half receiving the extra byte for odd lengths. Bit `0x08` prefixes `(kind + len(payload)) & 0xff` and suffixes the flags byte.

Kind transforms are: kind `0` leaves bytes unchanged; kind `1` reverses bytes; kind `2` rotates left by one byte; kind `3` emits rolling xor bytes where byte `0` stays unchanged and byte `i` becomes `in[i] xor in[i-1]`; kind `4` emits odd-indexed bytes followed by even-indexed bytes; kind `5` swaps each adjacent pair and leaves a final odd byte as-is.

Plan records are ordered. A legacy plan record is `[u8 scope_len][scope bytes][u8 kind][u8 action][u8 arg][u8 enabled]`. An extended plan record is `[u8 255][u8 scope_len][scope bytes][u8 kind][u8 action][u8 arg][u8 enabled][u8 window][u8 repeat][u8 salt]`. For each journal record, prefer enabled rules whose plan scope exactly matches the requested scope over enabled wildcard `*` rules for the same kind; within the same specificity, the last matching rule in physical order wins. Disabled plan rules are ignored.

Plan actions run after kind transforms. Action `0` leaves bytes unchanged. Action `1` xors each byte with `arg`. Action `2` rotates right by `arg modulo length`. Action `3` keeps indices where `index % max(1, window)` equals `arg % max(1, window)`. Action `4` appends the first byte `repeat` times and then appends `salt` if the payload is non-empty. Action `5` xors byte `i` with `(arg + salt + i * window) & 0xff`, then rotates left by `repeat modulo length`. Action `6` processes chunks of `max(1, window)` bytes, xors each byte with `arg`, and keeps the first occurrence of each resulting byte within that chunk; append `salt` exactly `repeat` times once globally if the combined result is non-empty. Action `7` appends the reverse of the payload-at-action-entry `repeat` times, truncates to `window` bytes when `window > 0`, and xors every remaining byte with `arg ^ salt`.

The `entries` response field is the number of enabled journal records that were actually folded for that response, including matching scope-specific records and matching `all` records, after applying the same scope rules as the fold algorithm. The daemon must not return stale folded bytes or stale entry counts after the journal or plan is rewritten while the daemon is running. Do not fetch anything from the network, and do not replace the service with a script that only handles the bundled seed files.
