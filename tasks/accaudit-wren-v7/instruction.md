The accounting team runs a nightly batch job that produces `/app/transactions.tsv`, a tab-delimited log of bank account activity. Write a Wren script at `/app/audit.wren` that reads this file and generates a JSON audit report at `/app/audit_report.json`. Run it with `wren_cli /app/audit.wren`.

Each row holds six tab-separated fields: `txn_id`, `account_id`, `date`, `amount`, `type`, and `currency`. A row is flagged `MISSING_FIELD` and skipped only when it splits into fewer than six tab-separated fields; a field that is present but empty does not count as missing, so an empty `date`, `amount`, `type`, or `currency` still flows through to its own format check below. Every other check applies only to complete rows (those with all six fields), and a complete row can trigger more than one format error: transaction IDs must be a `T` followed by exactly nine digits (`BAD_TXN_ID`); account IDs must be `AC` followed by exactly six digits (`BAD_ACCT_ID`); dates must be valid calendar dates in `YYYYMMDD` format no later than 2026-06-13 (`BAD_DATE`); amounts must be non-negative decimals — one or more digit characters with at most one decimal point and no other characters, so `5`, `5.`, `.5`, and `0.50` are all valid while an empty value, a sign, letters, or a second dot are `BAD_AMOUNT`; the type must be one of `CREDIT`, `DEBIT`, `FEE`, or `INTEREST` (`BAD_TYPE`); and the currency must be one of `USD`, `EUR`, `GBP`, `JPY`, or `CHF` (`BAD_CURRENCY`).

Two checks apply to every complete row regardless of its format validity: a transaction ID that has already appeared is flagged `DUPLICATE_TXN` on the second and any later occurrence, and a `FEE` whose amount exceeds 25.00 is flagged `FEE_OVERCAP`.

The remaining rules are per-account and operate only on each account's *valid records* — the complete rows that passed all six format checks and are the first occurrence of their transaction id. Process each account's valid records in chronological order, by date and then by `txn_id`. Maintain a running balance, in whole cents, that starts at zero: `CREDIT` and `INTEREST` increase it and `DEBIT` and `FEE` decrease it, and any `DEBIT` or `FEE` that drives the running balance below zero is flagged `OVERDRAFT`. If more than five `DEBIT` valid records for an account fall on the same calendar date, every one of those debits is flagged `HIGH_VELOCITY`.

The account also earns daily credit interest, which the audit reconciles against the posted `INTEREST` records. The annual rate is determined by the account's currency — the currency of its first valid record in chronological order — in basis points (a basis point is one hundredth of a percent). EUR is 800, GBP 900, JPY 500, and CHF 600 throughout. USD follows a published schedule: 1000 for dates before 2025-01-01 and 1200 on or after 2025-01-01. Interest accrues once per calendar day on the balance held that day, but only while that balance is strictly positive, using an Actual/Actual day count: each day's interest is `balance_cents * rate_bps` divided by `10000 * days_in_year`, where `rate_bps` is the rate in effect for the account's currency on that day and `days_in_year` is 366 in a leap year and 365 otherwise, rounded to the nearest whole cent with exact halves rounding up. The per-day cents are summed, each day rounded before it is added. Interest accrues over the days from one valid record up to, but not including, the next, at the balance in effect during that span. Each `INTEREST` record posts the interest accrued since the previous `INTEREST` record for that account (or since the account's first valid record); if the posted amount does not equal the accrued amount, flag the record `BAD_INTEREST`. A posted `INTEREST` amount, whether or not it matched, both resets the accrual to zero and is added to the running balance.

The output must be a JSON array whose elements each have four string fields: `txn_id`, `account_id`, `error_code`, and `detail` (a short human-readable description of the violation). Sort the array by `account_id` ascending, then by `error_code` ascending within an account, and finally by `txn_id` ascending to break further ties.
