Create /app/analysis.R for the risk queue at /app/data/risk_queue.csv. Historical rows have target populated, while blank-target rows are the evaluation period. record_id is the identifier, event_month defines the temporal split, and audit_group is only for validation reporting. The fields record_id, target, event_month, audit_group, ops_score_a, ops_code_b, and ops_bucket_c are leakage or post-review fields and must not be model inputs.

The historical modeling population is event_month < 10. The validation population is 8 <= event_month < 10, with earlier historical rows used for fitting; if hidden data mutation leaves either side with only one target class, use the fallback split in /app/contracts/outputs.md. Treat -999 and -777 as missing values. Predictions and the decision threshold must satisfy validation expected cost with false-negative cost 12 and false-positive cost 1.

The deliverables are predictions for blank-target rows plus validation scores, metrics, calibration, cost-curve, bootstrap, fairness, and feature-importance files. Exact filenames, columns, ordering, rounding, fallback details, and quality targets are in /app/contracts/outputs.md. The output set must regenerate correctly after /app/outputs is cleared.
