Finish a Go command-line tool that queries the live Go module proxy and resolves a module's dependency versions by Minimal Version Selection. A scaffold is waiting in /app: the proxy HTTP client and its response cache, the CLI wiring, and the shared types are all in place and working. The path escaping, the version ordering, the go.mod parser and the MVS build list are stubbed and currently return not_implemented or an unchanged input. Build the tool with go build -o /app/gomvs . and finish those cores.

Everything is read live from https://proxy.golang.org: the tool lists a module's published versions, fetches and parses a pinned version's go.mod, and walks the transitive go.mod graph to compute a build list. Nothing is bundled, so the network is genuinely required. Only the Go standard library is available; keep the code gofmt-clean and vet-clean.

The command surface, the exact stdout each command owes, the proxy endpoints, and the error tokens are documented in /app/docs/spec.md. Read that file before you start; it is the authoritative specification and the tests follow it precisely. The behavior it describes is standard Go module tooling - proxy path encoding, Go-module semantic-version precedence, the go.mod grammar, and Minimal Version Selection over the transitive graph - so implement those the way the go command does. All machine-readable output, including result tokens, goes to stdout, and failures use a non-zero exit code.
