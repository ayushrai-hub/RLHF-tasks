Milestone 3: Implement `python3 /app/tools/entitlement_audit.py remediate /app/bundles /app/policy/signing-policy.json /app/out/entitlement-remediation.json`. The command must reuse the same bundle discovery, plist parsing, entitlement sidecar selection, policy override, allowed-profile, app-group, associated-domain, and push-profile-environment rules from `inventory` and `plan`.

The remediation JSON must contain `fixes` and `summary`. Emit one fix row for every non-keep plan action, sorted by bundle id. Do not emit fix rows for keep actions. Each fix row must include `bundle_id`, `action`, `reasons`, `set_team_identifier`, `allowed_profiles`, `expected_push_environment`, `remove_app_groups`, `remove_associated_domains`, and `blocked`.

`set_team_identifier` is the effective policy team identifier when the row has `team identifier missing` or `team identifier mismatch`; otherwise it is null. `allowed_profiles` is the same effective allowed profile array from the action target. `expected_push_environment` is the same effective expected push environment from the action target, including null when no policy value applies. `remove_app_groups` is the sorted list of the bundle's app groups that do not start with the effective required app-group prefix. `remove_associated_domains` is the sorted list of associated domains that are not `applinks:` entries ending with an effective allowed associated-domain suffix. `blocked` is true when the plan action is `block` and false otherwise.

The summary must include integer `fix_count`, `blocked_count`, `update_count`, `team_identifier_fix_count`, `app_groups_to_remove_count`, `associated_domains_to_remove_count`, and `push_environment_fix_count`. Count a push-environment fix only when the reasons include `push environment profile mismatch`.
