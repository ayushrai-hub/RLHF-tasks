Milestone 4: Implement `python3 /app/tools/entitlement_audit.py apply-remediation /app/bundles /app/policy/signing-policy.json /app/out/entitlement-apply.json`. The command must reuse the same bundle discovery, entitlement sidecar selection, policy override, classification, and remediation rules from `inventory`, `plan`, and `remediate`.

For each bundle whose plan action is `update`, modify only that bundle's selected `*.entitlements` plist sidecar. Do not edit Info.plist files, signing-policy.json, source files, blocked bundles, keep bundles, or any file outside the bundle's selected entitlement sidecar. Remove app groups that do not start with the effective required app-group prefix, remove associated domains that are not allowed by the effective associated-domain suffixes, and when the reasons include `push environment profile mismatch` set `aps-environment` to the effective expected push environment. If removing app groups or associated domains removes every value from that entitlement key, keep the key present with an empty array rather than deleting it. If the effective expected push environment is null, do not set or remove `aps-environment`.

For each bundle whose plan action is `block`, leave files unchanged and report the bundle in `blocked`. The apply report must be JSON with `applied`, `blocked`, and `summary`. Sort `applied` and `blocked` rows by bundle id. Each applied row must include `bundle_id`, `path`, `changes`, `removed_app_groups`, `removed_associated_domains`, and `set_aps_environment`. `path` must be the absolute path to the entitlement sidecar that was changed. `changes` must list only the change categories that were actually applied, in this order: `remove_app_groups`, `remove_associated_domains`, `set_push_environment`. Each blocked row must include `bundle_id`, `path`, `reasons`, and `unchanged`, where `unchanged` is true and `path` is the selected entitlement sidecar path or null when no sidecar exists.

The summary must include integer `applied_count`, `blocked_count`, `files_changed`, `app_groups_removed`, `associated_domains_removed`, and `push_environments_set`. The command must be idempotent: after a successful run, running the same command again against the same files and policy must not report previously applied changes again and must set `applied_count`, `files_changed`, `app_groups_removed`, `associated_domains_removed`, and `push_environments_set` to 0 while still reporting currently blocked bundles.
