Milestone 2: Implement `python3 /app/tools/entitlement_audit.py plan /app/bundles /app/policy/signing-policy.json /app/out/entitlement-plan.json`. The plan must include `actions` sorted by severity (`block`, then `update`, then `keep`) and bundle id, plus a `summary` count for those three actions. Bundles may be plain directories rather than `.app`-suffixed directories; identify a bundle by an `Info.plist` file inside a child directory of /app/bundles. Read each bundle's profile from Info.plist's ProvisioningProfile key. For entitlements, prefer the bundle sidecar named `<CFBundleExecutable>.entitlements` when it exists; otherwise use the first available `*.entitlements` plist sidecar sorted alphabetically. The entitlement `team_identifier` must come only from the `com.apple.developer.team-identifier` key; do not infer it from keychain group prefixes.

Each action row must include `bundle_id`, `display_name`, `platform`, `profile`, `action`, `reasons`, and `target`. The `target` object must always include `team_identifier` as the effective policy team string, `allowed_profiles` as an array of strings preserving the effective policy order for that bundle, and `expected_push_environment` as a string or null when no policy value applies. The policy may include a `bundle_overrides` object keyed by bundle id. For a matching bundle, an override may replace `required_team_id`, `allowed_profiles`, `required_app_group_prefix`, `allowed_associated_domain_suffixes`, and `expected_push_environment`; omitted override fields fall back to the global policy. When no bundle override supplies `expected_push_environment`, derive it from the policy's `push_profile_environments` map using the bundle's `profile` value as the key; if that map has no entry for the profile, the effective expected push environment is null and imposes no push-environment constraint. The global policy's `allowed_profiles` is keyed by platform, such as `{ "ios": ["ios-prod"] }`, but `bundle_overrides.<bundle id>.allowed_profiles` is a flat array of profile strings for that bundle, such as `["ios-internal"]`; do not treat the override value as another platform-keyed map. Use `block` when the team identifier is missing or does not match the effective policy, or when the profile is not allowed for the platform or bundle override. Use `update` for app group prefix violations, associated domains outside the effective allowed suffixes, or an `aps-environment` that is present and does not match the effective expected push environment. If `aps-environment` is absent from the selected entitlement sidecar, skip the push-environment mismatch check; the mismatch check only applies to a present but wrong value. Use `keep` when no policy violations are detected for the bundle. Emit reasons in this order when multiple reasons apply: `team identifier missing`, `team identifier mismatch`, `profile not allowed for platform`, `app group prefix violation`, `associated domain not allowed`, and `push environment profile mismatch`.
