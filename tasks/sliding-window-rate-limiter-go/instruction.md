The sliding window rate limiter at `/app/` reads request traffic from `/app/data/traffic/`, simulates per-client rate limiting with a sliding window, detects burst violations, and generates a report. Configuration is in `/app/config/settings.json`. The tool has bugs causing incorrect rate limiting decisions. Fix all bugs so the output is correct, then rebuild with `/usr/local/go/bin/go build -o bin/rate-limiter ./cmd/limiter` and run `/app/bin/rate-limiter analyze --traffic /app/data/traffic --output /app/output --format both`.

Traffic files are loaded in ascending lexicographic order by filename. Each file contains an array of requests with `id`, `client_id`, `timestamp_ms`, `path`. Requests are processed chronologically. For each request, count the number of previously allowed requests from the same client within the window [timestamp - window_ms, timestamp) using inclusive start (requests at exactly the boundary ARE counted in the current window). A request is allowed if the window count is below `max_requests`. A burst violation occurs when `burst_limit` or more previously-allowed requests from the same client exist within `grace_period_ms` of the current request (the current request itself is NOT counted toward the burst threshold); this triggers a penalty blocking the client for `penalty_ms`.

The report JSON is written to `/app/output/limiter_report.json` and text to `/app/output/limiter_report.txt`. JSON must contain: `total_requests`, `allowed_count`, `denied_count`, `overall_deny_rate` (4dp), `decisions` (array with `request_id`, `client_id`, `timestamp_ms`, `allowed`, `window_count`, `reason`), `client_stats` (array with `client_id`, `total`, `allowed`, `denied`, `deny_rate`, `burst_events`, `penalty_ms`), `burst_events` (array with `client_id`, `timestamp_ms`, `count`, `limit`), `window_violations`. For each client_stats entry, `penalty_ms` is the total penalty time actually triggered for that client, equal to that client's `burst_events` multiplied by the configured `penalty_ms`; clients with no burst events must report 0. The `reason` field in decisions must be `"allowed"`, `"rate_exceeded"`, `"burst_exceeded"`, or `"penalty_active"` depending on the outcome. Text report must include "Sliding Window Rate Limiter Report", "Total requests:", "Denied:", "Deny rate:", "Window violations:". Output must be deterministic and the binary must exit non-zero with no arguments.

Settings from `/app/config/settings.json` are the sole authoritative source and must not be overridden by profiles, environment variables, or any other mechanism. All rate values (deny_rate in both overall and per-client stats) must be rounded to exactly 4 decimal places. The penalty period uses strict less-than: a request at exactly `timestamp + penalty_ms` is NOT blocked. Code comments, docstrings, and documentation files may contain errors.
