We have a pub/sub delivery validation system at /app that audits message delivery correctness across a distributed messaging platform. It ingests delivery logs and produces a correctness report, but the report currently does not match what the log says happened. We need /app/output/results.json to be accurate. Build with cd /app && go build -o /app/bin/pubsub-validator ./cmd/pubsub-validator and run the binary. Go toolchain is at /usr/local/go/bin. The config at /app/config/pubsub.toml is the single source of truth, nothing else in that directory should interfere. Code comments and documentation files may contain errors.

Subscription windows are half-open intervals where delivery at exactly unsub_ts falls outside valid range constituting an unsub_delivery violation at critical severity. Duplicates are scoped per-client so the same message reaching different subscribers is fan-out not duplication. Ordering groups by client and topic sorted by delivery timestamp requiring strictly increasing sequence numbers, violations at error severity. Mean interval uses floating-point division. Dead letters trigger when retry_count meets or exceeds configured max. Retention expiry uses strict greater-than against TTL so boundary-equal ages remain valid, where age equals delivery timestamp minus that msg_id's first-seen timestamp. The retention max_age and avg_age report exclusively over the expired population, only deliveries whose age strictly exceeds TTL contribute.

Priority scoring weights unsub, duplicate, ordering at 5, 3, 3 respectively, multiplied by delivery priority level and normalized against total deliveries. Backpressure threshold is half the float mean interval per topic, index is burst deliveries over topic total to 4 decimal places. Throttle uses floor division for bucket size, counts buckets exceeding 2 deliveries. Fanout ratio is deliveries over unique messages per topic rounded to 4 places and all rates use count over total deliveries at 4 decimal precision.

Full output specification with sort orders lives at /app/docs/output_schema.md. Binary must be valid ELF over 500KB with deterministic output.
