Make the database services work with explicit in-memory SQLite connections. `QueryScheduler(query_engine=None)`, `StepBuilder(..., query_engine=None)`, `UserService(query_engine=None)`, and `NodeService(node_engine=None)` should use injected connections when present and fall back to the lazy accessors only when they are not. The query database uses the singular table names `query_schedule`, `query_schedule_steps`, `human_users`, and optional `query_lock_events`; the node database uses `nodes` and `nodes_to_human_users`.

The query locker public call shape is `get_and_lock_query(country_node: str, human_user: dict, now=None, thread_id=None, ...)`, so callers pass the country string first and the human-user dictionary second. It should choose one non-deleted query for the user's pod/country with `scheduled_execution_date >= now` and `scheduled_execution_date <= now + 10 minutes`, ordered by `priority DESC`, then `scheduled_execution_date ASC`, then `id ASC`. Use a `SELECT ... LIMIT 1` candidate query and `fetchone()` for each claim attempt. Legacy rows may store `scheduled_execution_date` or `locked_at` with a space separator like `2026-01-01 12:04:00`; treat those values as equivalent to the `T`-separated ISO form for window checks, stale-lock checks, and ordering. Rows with `human_user_id` set are unavailable unless they have a `locked_at` older than 15 minutes. The second return value from `get_and_lock_query(...)` is `True` only when no candidate can be claimed; it is `False` for both fresh claims and stale-lock reclaims. When a row is claimed, update only that row's `human_user_id`, `locked_at`, and `locked_by_thread`; store `locked_at` with a `T` separator and second precision, like `datetime.isoformat(timespec="seconds")`. `thread_id` is optional on `get_and_lock_query(...)`, and omitted `thread_id` should leave `locked_by_thread` as `None`. Do not overwrite a row that becomes locked between selection and update, including when schedulers use separate SQLite connections; if the conditional claim update affects no row, re-run the ordered selection and try the next currently claimable candidate. Return `(None, True)` only after no claimable candidates remain. `unlock_query` clears those lock fields. If nothing is claimable, return `(None, True)`.

If the query database has an optional `query_lock_events` table, record scheduler audit events without requiring that table in older schemas. The table shape is `id INTEGER PRIMARY KEY AUTOINCREMENT`, `query_schedule_id INTEGER`, `human_user_id INTEGER`, `thread_id INTEGER`, `action TEXT`, `event_time TEXT`, `previous_human_user_id INTEGER`, and `previous_locked_at TEXT`. Insert `action = "claim"` for a fresh successful claim, `action = "reclaim"` for a successful stale-lock claim, `action = "race_miss"` when a selected row fails the conditional update because it changed before the claim, and `action = "unlock"` from `unlock_query`. Unlock events represent the post-unlock row state, so their `human_user_id`, `thread_id`, `previous_human_user_id`, and `previous_locked_at` values should be `NULL`; do not store the old claimer in `human_user_id` for unlock rows. Claim/reclaim/race event times should use the same ISO second timestamp as the claim attempt.

Keep the existing public shapes: `StepBuilder.build_query_steps(...)` returns dictionaries with `step_number`, `type`, `value`, `done`, `url`, and `title`, ordered by `position ASC` when that column exists and otherwise by `id ASC`. If `position` exists but a row's value is `NULL`, sort that row after all numbered positions and then by `id ASC`. `NodeService.get_online_nodes_and_user_pool()` returns `(online_nodes, user_pool)`, dedupes duplicate node/user mappings, and only includes online nodes. Each online-node entry should have `uuid` and `currently_online`; each user-pool entry should have `human_user_id`, `uuid`, `currently_online`, and `node_country`.
