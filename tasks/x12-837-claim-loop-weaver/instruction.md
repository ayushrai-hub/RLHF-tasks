Write a Go CLI that weaves sharded X12 837 professional claim segments into consolidated CLM/2400 loops. Put your program under `/app/cmd/claim-weaver/`, build to `/app/claim-weaver`, and run that binary (no arguments) to refresh `/app/output/woven-claims.json`, `/app/output/weave-summary.json`, and `/app/output/errors.log`. The tool also supports `claim-weaver ingest` (write `/app/state/weave-snapshot.json` and `/app/state/weave-ledger.json`) and `claim-weaver export` (reconcile snapshot + ledger → outputs only) per `/app/docs/weave-snapshot.md`. Only the Go standard library may be imported.

Shard `.edi` files live in `/app/data/shards/` with priorities in `/app/data/shard-manifest.json`. Loop hierarchy, ISA delimiter re-read, service line ordering, HI diagnosis pointer inheritance, CLM frequency supersession (including chained replacement claims), NM1 patient-name normalization (including U+00A0 to ASCII space), malformed-segment skipping, orphan LX and SV1 handling, weave-summary counters, idempotent output bytes, exit-code rules per subcommand, and output schemas are defined in `/app/docs/837-weave.md` and `/app/docs/error-log-format.md`. Replay is sequential per claim control number: processing service line N updates the inherited diagnosis pointer list that service line N+1 in that claim observes — an explicit HI segment also becomes the new inherited default for all subsequent 2400 loops in that claim until overridden.

Skip malformed segments per the contract. Orphan LX and SV1 segments that appear before their required parent loops must each increment `skipped_segments`, be logged to `/app/output/errors.log` with the raw segment text, and contribute to exit code `3` on the default run and on `claim-weaver export`. Exit code `3` still writes outputs from valid data. `claim-weaver ingest` always exits `0` even when segments were skipped; skipped counts are recorded only in the snapshot. After shard inputs change, run ingest before export. Shard inputs may change between runs; do not hardcode outputs.
