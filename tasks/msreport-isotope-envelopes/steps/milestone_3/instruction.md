Keep the /app mass-spectrometry CLI buildable with make from /app. Milestone 3 adds replicate review, and the centroid and envelopes commands from the previous milestones should still work.

Implement `/app/bin/msreport review --envelopes /app/out/envelopes.json --replicates /app/data/replicates.tsv --output /app/out/isotope-review.json` so it compares envelope families within each replicate group. The output JSON has `groups` as a flat array of per-group-family row objects sorted by group id and then family, plus a `summary` object.

For each group and family, report `group`, `family`, sorted `runs`, `observed_runs`, `missing_runs`, `mean_neutral_mass`, `mass_delta_ppm_by_run`, `representatives`, `ppm_span`, `intensity_cv`, and `status`. `mean_neutral_mass` is the mean observed neutral mass rounded to 5 decimals, or null when no envelope is observed. `mass_delta_ppm_by_run` maps each observed run to `(neutral_mass - mean_neutral_mass) / mean_neutral_mass * 1,000,000`, rounded to 2 decimals. `representatives` maps each observed run to the selected envelope's `scan`, `charge`, `peak_count`, `monoisotopic_mz`, `neutral_mass`, and `intensity_sum`. `ppm_span` is the max-minus-min neutral-mass span divided by the mean and multiplied by 1,000,000, rounded to 2 decimals. `intensity_cv` is population standard deviation divided by mean intensity, rounded to 4 decimals, or null when no envelope is observed. `status` is `missing` if any expected run lacks the family, `drift` if ppm_span is greater than 12.0, `unstable_intensity` if intensity_cv is greater than 0.35, otherwise `stable`. The summary includes `group_count`, `family_review_count`, and the status count keys `stable_count`, `drift_count`, `unstable_intensity_count`, and `missing_count`.

When the envelope file has more than one record for the same family and run, use one representative for review: prefer the highest `peak_count`, then the highest `intensity_sum`, then the lowest `monoisotopic_mz`.
