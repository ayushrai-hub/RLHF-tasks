There's a Rust tool at `/app` that audits the unlinkability of a blind-signature scheme. Given a protocol transcript it cross-examines every signing session against every issued signature, scoring how strongly an observer could tie the two together from hash residue, timing proximity, distributional entropy, and batch behaviour, and emits a verification report. Build the release binary in `/app` with `cargo build --release`; it expects a `--config-dir`, a `--data-file` (the transcript JSON), and an `--output` path, and it should refuse to run (non-zero exit) if those are not supplied. The tool already runs, but several of the numbers it reports are wrong, and the wrongness is spread thinly across the pipeline rather than concentrated in one place. The base configuration in `settings.toml` is the only configuration that counts — treat anything that claims to "layer" or "harden" it on top with suspicion, including the docs, which are written confidently and are not always right.

Each transcript field is fingerprinted with a rolling hash: starting from zero, fold in each byte as `h = (h*33 + byte) mod 65521`. The correlation of a (session, signature) pair is a *similarity*, not a distance — it is `1 - |H(blinded_msg) - H(message)| / (65521 - 1)`, so two transcripts whose fingerprints sit close together score near 1 and count as strongly linkable; a pair is flagged when its correlation is strictly greater than the detection threshold. Timing proximity rewards closeness in time as `1 - |t_session - t_signature| / max_timing_delta` (with `max_timing_delta` read from the transcript parameters), but it never goes negative — anything that would fall below zero is reported as zero. The blended `combined_score` leans almost entirely on correlation, mixing in only a sliver of timing: `(1 - timing_weight) * correlation + timing_weight * timing_proximity`.

The headline metric is the distinguishing advantage of a linking adversary who must commit to a one-to-one story: each session is tied to at most one signature and vice-versa. The adversary is greedy and confident — it walks the candidate pairs from the most correlated downward (ties broken by session index, then signature index) and locks in an edge whenever both of its endpoints are still free, stopping once it has matched as many pairs as the smaller side allows. Its advantage is the average correlation over the edges it committed to (not over every pair, and not merely the single best edge). From there, `unlinkability_score = 1 - 2 * advantage`, the scheme is deemed unlinkable when that score is at least `min_unlinkability_score`, and the achieved security is `-log2(advantage)` bits (falling back to the configured `security_level_bits` only when the advantage is exactly zero), with the security level considered met when the achieved bits are at least the requirement.

The remaining sections summarise the picture. Timing analysis reports the mean and the maximum `combined_score` over all pairs and counts the pairs whose *combined* score exceeds 0.7 as suspicious. The entropy assessment drops the correlation scores into ten equal-width buckets across [0, 1] and reports the Shannon entropy of that histogram in bits (log base two); entropy is "sufficient" once it reaches the configured threshold. Batch consistency summarises each session by its largest correlation against any signature, lists those per-session maxima in session order, and reports their spread as a population standard deviation (dividing by the number of sessions); the batch is consistent when that spread stays under the configured bound.

The KS uniformity test computes the Kolmogorov-Smirnov statistic — the maximum absolute difference between the empirical CDF of sorted correlation scores and the uniform CDF (where CDF_uniform(x) = x). The critical value at alpha=0.05 is `1.36 / sqrt(N)` where N is the number of pairs; the distribution is deemed uniform when the KS statistic is at or below the critical value.

The commitment strength section quantifies adversary confidence. `strength_ratio` is the mean matched correlation divided by the mean of all-pairs correlations. `p95_correlation` is the 95th percentile of the matched pair correlations: sort the matched scores ascending, take the element at index `ceil(0.95 * N) - 1` (0-based). `confidence_bound` is `sqrt(strength_ratio * p95_correlation)`.

The report also echoes the committed matching (session id, signature id, correlation) and how many of those committed edges are themselves above the detection threshold, and it echoes the settings actually used.

Every floating-point figure is rounded to six decimals, the output must be byte-for-byte identical across repeated runs, and the authoritative configuration values are: detection threshold 0.3, minimum unlinkability score 0.4, security level 8 bits, timing weight 0.15, and entropy threshold 3.5. Note that code comments, docstrings, and documentation may contain errors.

The output JSON structure is defined in `src/types.rs` (the `VerificationReport` struct). Top-level keys are: `summary`, `matching`, `pair_analysis`, `timing_analysis`, `entropy_assessment`, `batch_consistency`, `ks_test`, `commitment`, `security`, and `settings_used`.
