The lightweight TCP analysis tool in `/app` is meant for incident triage when engineers only have packet metadata exported to CSV, not a real pcap or libpcap/tshark stack. Right now the C++ CLI builds, but its sequence tracking is too shallow: retransmits, segments that arrive beyond a gap, bidirectional streams, resets, and late packets that fill an earlier gap are all blended together.

Build with `/app/scripts/build.sh`; the fixed binary must be `/app/bin/flowgap`. The CLI is `flowgap --csv <absolute-path> --out <absolute-path> [--stream <stream_id>]`. Relative `--csv` or `--out` paths must exit with status `2` and print `csv path must be absolute: <value>` or `out path must be absolute: <value>` on stderr. Missing required flags, missing flag values, or unknown flags must exit with status `2` and print `usage: flowgap --csv <absolute-path> --out <absolute-path> [--stream <stream_id>]` followed by a newline on stderr.

The CSV and JSON contract is part of the task and lives in `/app/docs/flowgap_contract.md`. In short, read RFC-4180-style packet metadata rows grouped by `stream_id` in capture order, ignore malformed data rows with diagnostics that use CSV file line numbers, and write compact JSON ending in a newline. Within each stream, track independent sequence state per `src -> dst` direction; segment output must include that direction and classify rows as `in_order`, `out_of_order`, `retransmit`, `overlap`, `zero_length`, or `reset`. SYN and FIN each consume one sequence number in addition to payload bytes, while valid reset rows abandon open gaps for only their direction and reinitialize that direction's later sequence accounting. Record every observed gap with its direction and whether it was later `filled`, remains `open`, or became `abandoned`; keep deterministic stream, segment, gap, diagnostic, and summary ordering. The `rows_read` count includes every non-blank data row after the header before validity checks or stream filtering; `rows_skipped` is the malformed subset of those rows, including invalid integers, invalid TCP flags, duplicate packet numbers within a direction, timestamp regressions within a direction, and wrong-width rows.

The shipped fixture is only a smoke sample. Runtime validation will generate new CSV files with different stream names, quoted CSV fields, blank lines, packet numbers, sequence ranges, repeated out-of-order packets, overlaps, ACK-only rows, resets, opposite-direction packets sharing one stream, empty stream-filter results, malformed rows, and cascading gap-fill patterns, so the implementation needs to perform real TCP-style interval accounting rather than matching the fixture.
