Reconcile the completed settlement against the prior ledger snapshot. Read `/app/output/settlement.db`, `/app/prior-ledger/prior-account-months.csv`, and the `manual_adjustments` table in `/app/catalog/meter_catalog.db`, then write `/app/output/reconciliation-report.json`. The required report shape is also documented in `/app/docs/reconciliation-format.md`.

Use the union of `(account_id, service_month, district)` keys from the current `account_months` table and the prior ledger CSV. For each key, write one row with exactly these fields: `account_id`, `service_month`, `district`, `status`, `settlement_total_cents`, `prior_total_cents`, `delta_cents`, `settlement_kwh`, `prior_kwh`, `delta_kwh`, `adjustment_cents`, `adjustment_reason`, and `final_total_cents`.

Calculate `delta_cents` as current total minus prior total. Calculate `delta_kwh` the same way and round it to three decimals using half-up rounding. Use zero for a missing side only when calculating delta values. In the row fields themselves, if there is no prior ledger row, set `prior_total_cents` and `prior_kwh` to `null`. If there is no current settlement row, set `settlement_total_cents`, `settlement_kwh`, and `final_total_cents` to `null`.

Set `status` to `new` when the key exists only in the current settlement, `missing_from_settlement` when it exists only in the prior ledger, `unchanged` when both current and prior cents and kWh match exactly, and `changed` otherwise. Join `manual_adjustments` by the same key. Use `0` for `adjustment_cents` and `null` for `adjustment_reason` when no adjustment exists. Set `final_total_cents` to the current settlement total plus `adjustment_cents` when a current settlement row exists.

The report should contain `generated_from`, `row_count`, `status_counts`, `net_delta_cents`, `net_adjustment_cents`, `final_total_cents`, and `rows`. Set `generated_from` to `["/app/output/settlement.db", "/app/prior-ledger/prior-account-months.csv"]`. Set the top-level `final_total_cents` to the sum of all row-level `final_total_cents` values, treating `null` as zero. The `status_counts` object must include all four keys: `changed`, `missing_from_settlement`, `new`, and `unchanged`, even when a count is zero. Sort rows by service month, then account id, then district. Preserve the existing settlement database and settlement summary outputs.
