We need a clean settlement feed before billing can start. Read the raw meter logs under `/app/raw-events` and the SQLite catalog at `/app/catalog/meter_catalog.db`, then write `/app/output/normalized-events.jsonl`.

The output should contain one JSON object per accepted meter event with these fields: `event_id`, `observed_at`, `account_id`, `meter_id`, `service_month`, `district`, `adjusted_kwh`, `source_quality`, and `billing_band`. Keep the newest revision for duplicate event ids, break any same-revision tie with the higher source priority, and if those still tie keep the event with the later `received_at` timestamp. Ignore events whose quality is not `valid` or whose meter was not active at the observed timestamp.

After joining the event to its meter, derive `service_month` with the meter district's row in `district_billing_windows`. Add `utc_offset_hours` to `observed_at` and use the resulting local timestamp. If the local day is before `cutover_day`, or it is the same day and the local hour is before `cutover_hour`, assign the event to the previous local month. Otherwise assign it to the local month. Set `billing_band` from the same local timestamp: use `peak` only when the local day is Monday through Friday, the local date is not in `district_holidays`, and the local hour falls inside the district's `district_peak_windows` start-inclusive, end-exclusive range; use `standard` otherwise. Most accepted rows use `kwh` as interval usage. For rows where `reading_type` is `register`, derive interval kWh from `register_kwh` by comparing it with the previous accepted register reading for the same meter, starting from `meter_register_baselines`; if the register went backwards, apply `rollover_kwh` before subtracting. Multiply interval kWh by the meter multiplier using decimal arithmetic before rounding, round `adjusted_kwh` to three decimals using half-up rounding, and sort rows by service month, account id, observed timestamp, then event id.
