# Mount Propagation Recovery Desk

Operators replay desk regression from `/app/environment` with `/usr/local/bin/ctl_r7` and case inputs under `/app/environment/data/cases/`. Exported matrix records at `/app/output/r7_matrix_record.json` disagree with sidecar replay, checkpoint seeds, persisted lane state, and `/usr/local/bin/chain_ref` on several slugs even when a single invoke looks superficially healthy.

Back-to-back runs with the same slug sometimes diverge on disk. Switching slugs in one process can leave stale material in later exports. Multi-entity cases occasionally emit shortened rosters or drop reconcile evidence after deep passes. Long interleaved slug chains can inject spurious observations or stall reconcile when generation floors disagree with persisted lane state. Shared entities across case rosters can resurrect book cells from an earlier scenario during recover. Malformed or truncated lane-state files must not wedge later runs; the desk should rebuild exports from sources alone after bad state is encountered.

Repair Rust sources under `/app/environment` only. Rebuild release desk binaries from that workspace before rerunning cases. The verifier rebuilds `ctl_r7` and `chain_ref` from your sources before scoring; hand-patched binaries or static matrix records will not pass. Library behavior under `/app/environment` must be correct, not only CLI output. Do not edit tests or hand-write `/app/output/r7_matrix_record.json`. The desk must regenerate output through the normal pipeline. Deleting a stale matrix file and rerunning must rebuild from sources alone. Repeat runs must yield byte-identical output when the active slug and lane state are unchanged.

Record shape and export invariants are defined in `/app/environment/schemas/r7_matrix.schema.json` and `/app/environment/docs/r7_tier_rules.md`, including scenario, chain_hex, rows, observations, evidence, entity, path_key, uri_key, ref_key, marker, book_cell, wave, phase, and branch semantics. Valid exports treat stale cache suffix decoration, compact wave marker tags, internal run-stamp aliases, and wal_replay observation rows as false positive states that must not appear. After a slug pivot, persisted wal observation keys must not retain material from prior slugs before the next export commits. Case JSON files name the active entity roster, segment, checkpoint stem, and cycle count for each slug. Checkpoint blobs use `marker_<entity>=` seed lines keyed to roster entities. Generation must advance on repeat runs of the same slug and WAL tails must not bleed across slug switches. Behavioral detail is split across docs, sidecar segments, checkpoint blobs, propagation tables, and the wired import graph.

Regression spans the desk case slugs shipped under `/app/environment/data/cases/`. When `mp_echo` runs after other slugs in the same process, its export must match an isolated `mp_echo` run for roster, segment cells, and checkpoint markers without cross-slug observation bleed.
