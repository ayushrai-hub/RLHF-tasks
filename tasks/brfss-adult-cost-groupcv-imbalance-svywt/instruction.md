Hey, quick one. Three years of pooled BRFSS adult survey responses sit at /home/data with a training file holding the HAVEDIAB target column and a separate held out file that does not. You cannot read the held out HAVEDIAB from the agent container; estimate your metrics by cross validation on the training side and report those CV-side numbers in metrics.json. The grading code independently recomputes the true held out values from the predictions you write and compares them with your reported numbers within tolerance. The R toolchain is installed system wide with glmnet, survey, Matrix, dplyr, readr, tidyr, stringr, and jsonlite; the Python venv only has numpy and pandas; the R helpers under /home/helpers are a fast path. There is no network at runtime.

The wrinkle is the split: training rows come from one set of US states and held out rows from a different set, so models must generalize across geography rather than memorise within state quirks. Diabetes prevalence here is roughly one in nine, so plain accuracy misleads and balanced_accuracy is the headline metric, with the bar set well above a majority class baseline; expect to need cross state feature work, survey weighted training, and threshold tuning. Discrimination via auroc, calibration via brier_score, and screening cost via cost_weighted_loss against the documented cost matrix at /home/data/brfss_cost_matrix.csv also matter, and every held out state with a non-trivial row count is graded individually, so a model that does well on average but collapses on a few states will not pass.

Write /home/output/predictions.csv with one row per held out row_id and columns row_id, pred_label valued 0 or 1, and pred_proba_positive in the unit interval, sorted by row_id ascending and covering every held out row_id exactly once. Write /home/output/metrics.json with these top-level keys: n_train, n_test, primary_metric_value equal to balanced_accuracy, balanced_accuracy, auroc, brier_score, per_class_recall, per_class_precision, cost_weighted_loss, cost_matrix, decision_threshold, group_field, n_states_train, n_overlap_states, weighted_prevalence_train, weight_field, strata_field, and psu_field. /home/SCHEMA.md is the full contract: it gives the exact type and shape of every key, including the nested objects and the literal BRFSS design column names, how to derive the cost figures, and the precise wording of every quality bar and tolerance. Follow it for anything left implicit here.
