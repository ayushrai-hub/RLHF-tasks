A host policy compiler applies nftables rule batches through a durable journal. Interrupted applies and restarts leave cases where the readiness probe reports a green lane while the audit view has drifted from replayed state. Fix the Go source under `/app/environment` so the normal audit pipeline regenerates `/app/output/audit_report.json`; hand-written output or test edits are not sufficient. Run `go run /app/environment/cmd/nfrd audit --profile <name>` for the gate, depot, and yard profiles. The verifier may also run `go run /app/environment/cmd/laneprobe yard`.

The audit report is JSON. Its top level carries profile, epoch, counter, runs, entries, and checkpoints. The runs, entries, and checkpoints values are lists. A run row records run_id, phase, and tree_hash. An entry records rule_id, action, epoch, and observed_hash, where action is the report phase; entries are emitted in rule_id, epoch, then action order. A checkpoint records run_id, phase, first_seq, last_seq, record_count, epoch_floor, epoch_ceil, and tree_hash. Phases are apply and settle. Hash strings use the digest format documented in the environment overview, and boolean verdict fields should not appear.

Derive the report from the durable journal state for the selected profile. Readable companion journal files are JSON lists and are part of the same recovery view as the primary batch: duplicate replay rows must not change the canonical view, malformed primary state must not hide usable replay state, and phase/run boundaries must remain isolated. Some recovered rows may carry a profile owner in the JSON field `"profile": "<name>"`; rows whose profile is another profile are residue and must be ignored before epoch, counter, checkpoint, and entry computation for the active profile. Duplicate rows share the same seq, run_id, phase, rule_id, and action; the retained row is the one with the greatest epoch, breaking ties by later source order. Rows are ordered by seq after canonicalization; a later row for the same rule replaces that rule's priority, epoch, and mark, including rows whose fixture action is undo. Empty phase segments use zero sequence and epoch spans. The tree hash uses compact JSON rows containing sorted rule_id, priority, and epoch; the observed hash uses compact JSON with rule_id, priority, epoch, and mark. The top-level epoch keeps the greatest value implied by persisted metadata, the layout manifest, and replayed records. The top-level counter is the maximum of the layout counter, persisted counter, and canonical row count after deduplication. A successful audit also updates `/app/output/state/<profile>/epoch.json` with lowercase keys `epoch`, `counter`, and `tag`, where epoch and counter match the values used in the report; lane probe output is advisory and must not override later journal evidence. Reruns must stay stable across crash residue, out-of-order spill records, stale metadata, malformed primary batches, owned residue from other profiles, and green lane probes.
