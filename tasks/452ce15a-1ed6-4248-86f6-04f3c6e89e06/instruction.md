Staged `beam-envelope` reports may list mixed revision metadata and envelope numbers in one JSON file. Reusing a combination label on a later stage journal sometimes returns an older envelope.

Repair the C++ implementation under `/app/environment` so staged updates are atomic, rejected amendments leave committed results unchanged, and every generated combination report is internally consistent. Static or manual JSON writes are insufficient; grading rebuilds from `/app/environment` and reruns the normal command pipeline.

Build with `bash /app/environment/scripts/build.sh`. Run `/app/environment/bin/beam-envelope --stage <path>... --combine <name> --out <report.json>`; sample journals live under `/app/environment/fixtures/` including staged amend examples, and grading expects `/app/output/envelope_report.json`. The report must include `schema_version` (2), `beam_id`, `combination`, `provenance` (`committed_revision`, `amendment_generation`, `accepted_stages`, `rejected_stages`), `envelope` reaction and response extrema, and `report_digest` as defined in `/app/environment/docs/report-format.md` and summarized in `/app/environment/docs/contract.md`. Piecewise discontinuity semantics and equilibrium invariants are documented in `/app/environment/docs/load-semantics.md`.
