# Signal scoring index

Now extend the same Go CLI in `/workspace` with the second command:

`go run /workspace/cmd/claimtower score --claims-in <claims.json> --signals-root <dir> --rules <rules.tsv> --signals-out <tsv> --index-out <json> --issues-out <tsv>`

This milestone builds on the claim JSON produced by milestone 1. The command should read the claim report, a rules TSV, and recursive plain `.signal.jsonl` / gzip `.signal.jsonl.gz` signal files. Follow `/workspace/docs/claimtower-contract.md`, especially the Milestone 2 section and its canonical issue-detail table, for the visible schema details.

The rules TSV header is exactly `code\tbase_points\tage_days\tmultiplier\tlabel`. If that header is malformed, emit the header issue and continue parsing remaining rows positionally against that fixed column order so later bad rows can still emit `rules_row`. Signal rows are JSON objects with claim id (`claim_id` or `id`), signal code (`signal_code` or `code`), revision (`revision` or `rev`), `observed_on`, `strength`, and optional `action`. Strength must be 1 through 5. Action defaults to active; if the selected latest row for a claim/code has action `retract`, remove that candidate. For each claim/code, select highest revision, then lexicographically smaller absolute source path, then lower source line. Recover and report malformed rows, non-object rows, missing or bad fields, future observed dates, absent claims, and absent rules using issue kinds `invalid_signal`, `missing_claim`, and `missing_rule` with the exact `detail` tokens defined in the contract, including `bad_json`, `not_object`, field names, `observed_on_after_as_of`, the signal code for `missing_claim`, and the missing signal code for `missing_rule`.

Score each active selected signal as `base_points + strength*2 + claim.severity*3 + reserve_gap_bonus + age_bonus`, where `reserve_gap_bonus` is floor((reserve - paid) / 10000) but never below zero, and `age_bonus` is the rule multiplier only when the claim age is at least the rule `age_days`. Write `--signals-out` with header `claim_id\tsignal_code\tlabel\tscore\tstrength\tobserved_on\tclaim_severity\tage_days\tsource_file\tsource_line`; the `age_days` column is the claim's computed age from the claim JSON, not the rule threshold. Sort by claim id, descending score, then signal code. Write `--index-out` as 2-space indented JSON with a final newline and with `as_of`, `claim_count`, `candidate_count`, and `claims`; `claim_count` must be copied from the input claim report, `candidate_count` must equal the number of scored rows written to `--signals-out` excluding the header, include only claims with at least one active scored signal in the `claims` array, sort claims by descending total score then claim id, and sort each claim’s signals by descending score then `code`. Each nested signal object inside `claims[].signals[]` must use JSON field names `code`, `label`, `score`, `strength`, and `observed_on`; do not use `signal_code` inside the nested JSON object. The issue TSV uses the same header and ordering as milestone 1. Keep parent-directory creation, final newlines, deterministic output, and Go standard-library-only constraints.
