The ODE callback harness under `/app/environment` produces `/app/output/run_summary.json` and `/app/output/trace.csv` that no longer match the published integration contract in `/app/environment/docs/contract.md`. Row-level metrics, event timing, carry scaling across plan rows, bundle digest tokens, and CSV trace fields disagree with the contract for the bundled plan, hook table, and overlay configuration.

Rebuild the release binaries from `/app/environment/Cargo.toml`. The harness installs to `/app/bin/ode_harness`; the probe helper installs to `/app/bin/ode_probe`. Regenerate both output artifacts by running the harness against `/app/data/ode_plan.tbl`, `/app/data/hooks.tbl`, and `/app/cfg/ode_overlay.toml`. The harness persists row-to-row checkpoint state in `/app/cfg/ode_checkpoint.json` with integer field `last_event_step`; downstream metric scaling must reflect that file across successive plan rows. Hand-written JSON or CSV will not satisfy the contract.

`run_summary.json` carries `schema_version`, `cases`, and `digest`. Each case includes `tag`, `event_step`, `metric_integral`, `order_sensitive`, `euler_ok`, `event_ok`, `restart_ok`, `metric_ok`, `summary_ok`, and `report_line`. `trace.csv` mirrors those fields in plan order. Probe mode names and environment keys are listed in `/app/environment/docs/schema_stub.json`; digest formatting, boolean spellings, checkpoint carry, and integration semantics are defined in the contract. Additional valid plan rows, hook tables, and overlay values may be supplied at run time under the same schema.
