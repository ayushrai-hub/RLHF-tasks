1. OVERVIEW OF POLAR STATION TRIAGE
================================================================================
The polar camera station records high-cadence sky frames for aurora monitoring.
Satellite bandwidth is limited, so the host has to classify frames locally, apply
environmental and sensor rules, and emit compact JSON artifacts for downstream review.

================================================================================
2. DISCUSSION ON CLASSIFIER THRESHOLDS
================================================================================
- Initial proposal (Jan 10): Classify images and escalate if strong aurora probability
  is above 90% (0.90).
- Revision (Jan 22): 90% is too high, we missed several minor events. Let's reduce the
  probability threshold to 80% (0.80).
- Field note (Feb 3): A few archive examples mention 88% as a temporary analysis cut,
  but that was not accepted as an operational action threshold.
- Final decision: We have standardized the strong aurora probability threshold to
  strictly 85% (0.85). If the model's confidence for 'strong_aurora' is 0.85 or higher,
  we must flag the frame and set the action to "escalate".

3. MEETING NOTES: TEMPERATURE ALERTS & SENSORS (FEB 18, 2026)
================================================================================
Date: February 18, 2026
Attendees: Dr. Marcus (Lead Scientist), Elena (Software), Dr. Chen (Instruments)

- Marcus: We noticed that when the ambient temperature drops significantly, the camera
  lenses accumulate ice crystals, creating fake aurora-like reflections.
- Elena: If we have ice crystals, a "weak_aurora" prediction could be a false positive.
  What temperature should trigger a quarantine?
- Marcus: In Jan, we suggested -20C. On Feb 5 we tested -30C but that was too cold.
  Let's settle on strictly below -25C (-25.0 degrees Celsius).
  If the ambient temperature is strictly below -25C, any "weak_aurora" prediction must
  be quarantined.
- Elena: So a "weak_aurora" with temperature < -25C is quarantined. What about "no_aurora"?
- Marcus: No, if there is no aurora, we don't care about the ice crystals. Just archive it.
- Elena: And what is the quarantine action name?
- Elena: We'll output the action as "quarantine" and set the flagged bit to true.
- Chen: What about the sensor classification?
- Marcus: Sensors SNS-001, SNS-002, and SNS-003 are fully trusted. But SNS-999 has a
  defective temperature sensor and filter wheel.
  Any frame originating from sensor ID "SNS-999" must be quarantined immediately:
  action is "quarantine" and flagged is true. This rule overrides all other prediction
  and temperature logic.

4. EMAIL THREAD: TARGET ACTION STANDARDIZATION
================================================================================
From: Elena <elena@polarstation.internal>
To: Dev-Team <dev@polarstation.internal>
Subject: Output format for prediction artifacts

For the predictions output, the worker must write a JSON file for each frame inside
the directory specified by the Terraform output "predictions_directory". If a frame
is named "frame_001.png", its prediction output must be named "frame_001_result.json".

The keys in each prediction JSON file must be:
- frame_id (string, e.g., "frame_001")
- aurora_class (string, one of: "no_aurora", "weak_aurora", "strong_aurora")
- probability (double/float, model's confidence for the predicted class)
- action (string, one of: "archive", "quarantine", "escalate")
- flagged (boolean, true or false)

The worker must write a summary of the run to "/app/output/run_summary.json" containing
integer fields total_processed, escalated_count, quarantined_count, and archived_count.

================================================================================
5. POST-MORTEM: INCIDENT #1102 - SENSOR SNS-999 CALIBRATION FAILURE
================================================================================
On February 14, SNS-999 generated thousands of false alarms due to the filter wheel
sticking. The incident review concluded:
"SNS-999 output is unreliable. Until replaced, all data from SNS-999 must go to
quarantine. No prediction or temperature check should override this quarantine state."
