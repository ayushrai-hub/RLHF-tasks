The Rust crate in `/app/task_file` is `tmpfiles_audit`, a small simulator for the tmpfiles-style boot cleanup policy we run on ephemeral Linux hosts. It compiles config fragments plus an in-memory filesystem snapshot into a deterministic action plan, but several parser and planner behaviors are wrong. Make the crate match `docs/SPEC.md` and `docs/format.md` without changing the public API.

The verifier builds against the public structs and calls `TmpfilesConfig::compile_plan` directly, so keep the exported type names, fields, enum variants, and method signature intact. The docs are the contract for vendor file masking, config ordering, quoted field parsing, path normalization and rejection, first-matching create/adjust precedence, existing-entry ensure behavior, globbed cleanup including recursive `R` roots and excludes, age parsing, symlink rules, error reporting, and deterministic output ordering. Pay close attention to cleanup: create/adjust claiming does not shield a path from cleanup, while a recursive parent removal absorbs descendant removals unless a protected or too-young descendant blocks the parent. Grading includes both fixed scenarios and generated configurations that combine those rules.
