Finish the reconciliation feature in the `/app` HTTP API.

Keep all milestone 4 behavior working, then add `POST /v1/reports/reconcile`. The request body must be JSON with `baseline_report_id`, `candidate_report_id`, optional `min_abs_delta` defaulting to 0, optional `tier_multipliers`, and optional `suppress_statuses`. Look up both report ids from the current server's in-memory report store. Return 400 for malformed JSON, missing report ids, negative `min_abs_delta`, non-positive tier multipliers, or a suppressed status outside `new_metric`, `removed_metric`, `regressed`, and `improved`. Return 404 when either report id is not in memory.

Compute the same metric changes as `POST /v1/reports/compare` using the supplied threshold, then remove any change whose status appears in `suppress_statuses`. For each remaining change, emit an action with `service`, `tier`, `metric`, `status`, `delta_sum`, `absolute_delta`, `impact_score`, and `recommendation`. Use the candidate report's tier for `new_metric`; use the baseline report's tier for `removed_metric`; for `regressed` and `improved`, prefer the candidate tier and fall back to the baseline tier. The default tier multiplier is `2.0` for `critical` services and `1.0` for every other tier. Values in `tier_multipliers` override the default for their matching tier. Compute `absolute_delta` as `abs(delta_sum)` and compute `impact_score` as `absolute_delta * tier_multiplier` rounded to the nearest 0.01. Use these rounded impact scores for action sorting, totals, and all budget-limit calculations.

Set `recommendation` to `investigate_candidate` for `new_metric` and `regressed`; set it to `verify_reduction` for `removed_metric` and `improved`. Sort actions by descending `impact_score`, then service name, then metric name; when two actions have the same `impact_score`, the service and metric ordering must determine their final order regardless of status or tier. The successful response must include `baseline_report_id`, `candidate_report_id`, `min_abs_delta`, sorted `suppressed_statuses`, `actions`, and `totals`. If `suppress_statuses` is omitted or empty, `suppressed_statuses` must be an empty JSON array `[]`, not `null`. The `totals` object must include `action_count`, `total_impact_score`, `by_status`, and `by_tier`, counting only emitted actions.

The request may also include optional `impact_budget` with optional `max_total_impact`, optional `tier_limits`, optional `service_limits`, and optional `status_limits`, for example `{"max_total_impact": 25, "tier_limits": {"critical": 15, "standard": 10}, "service_limits": {"Search API": 12}, "status_limits": {"regressed": 8}}`. A supplied `max_total_impact`, every supplied tier limit, every supplied service limit, and every supplied status limit must be non-negative, otherwise return 400. Service limit keys must be normalized with the same trim/lowercase/punctuation-collapse rule used for service names before they are echoed and enforced, so a limit for `Search API` applies to the canonical service `search-api`; a service limit key that normalizes to an empty string must return 400. Every key in `status_limits` must be one of `new_metric`, `removed_metric`, `regressed`, and `improved`, otherwise return 400. When `impact_budget` is present, keep the regular `actions` and `totals` unchanged, then add `budget_plan` to the response. Build the plan by scanning the already sorted `actions` in order. Select an action only when adding its `impact_score` would not exceed `max_total_impact`, would not exceed that action tier's limit in `tier_limits`, would not exceed that action service's normalized limit in `service_limits`, and would not exceed that action status's limit in `status_limits`. If any cap would be exceeded, defer that action and keep scanning later lower-impact actions. Limits for tiers, services, or statuses with no emitted action are echoed but do not affect selection. Preserve the original action order separately within `selected_actions` and `deferred_actions`.

The `budget_plan` object must echo `max_total_impact` when it was supplied, echo `tier_limits`, echo `service_limits`, echo `status_limits`, include `selected_actions`, include `deferred_actions`, include `deferred_reasons`, and include `totals`. When `impact_budget` omits `tier_limits`, `service_limits`, or `status_limits`, echo that omitted map as an empty JSON object `{}`. Echo supplied zero limits and limits for tiers, services, or statuses that have no emitted actions, but do not add those unused or zero-count keys to the selected/deferred breakdown maps. For each deferred action, add one `deferred_reasons` entry with `service`, `metric`, and `reasons`. The `reasons` array must use this order and include only caps that would have been exceeded at the moment that action was scanned: `max_total_impact`, `tier_limit`, `service_limit`, `status_limit`. Budget totals must contain `selected_count`, `deferred_count`, `selected_impact_score`, `deferred_impact_score`, `selected_by_tier`, `deferred_by_tier`, `selected_by_service`, and `deferred_by_service`. The four breakdown maps `selected_by_tier`, `deferred_by_tier`, `selected_by_service`, and `deferred_by_service` must contain integer action counts, not impact score sums, and must omit keys whose count is zero. If `impact_budget` is omitted, do not include `budget_plan` in the response.
