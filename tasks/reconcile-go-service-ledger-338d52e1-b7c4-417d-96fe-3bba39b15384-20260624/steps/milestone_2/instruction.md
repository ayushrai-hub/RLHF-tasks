Continue in `/app`. Now fix the event summarizer:

`go run ./cmd/ledger summarize --config /app/configs/rules.json --events /app/events.jsonl --out /app/out/summary.json`

The `/app/events.jsonl` path above is an example of the CLI shape; the implementation must accept any readable path supplied through `--events` and must not depend on a pre-staged file at that exact location. Events are newline-delimited JSON objects with `event_id`, `service`, `occurred_at`, `metric`, `value`, `source`, `sequence`, `kind`, and optional `correction_of`. Use the normalized config from milestone 1, and normalize each event `service` with the same trim/lowercase/punctuation-collapse rule before alias lookup so service aliases all roll up to the canonical service. Deduplicate by `(source, event_id)`, keeping the larger `sequence`; if the sequence ties, keep the later RFC3339 `occurred_at`. A `kind: "correction"` event replaces the contribution of the effective event whose `event_id` equals `correction_of`, even when the correction has a different `source`; count the correction event as the live event and include the correction event's source in that service's `sources` list. If more than one correction targets the same original event id, keep only the newest correction by the same sequence and `occurred_at` tie-break rule. Corrections can target earlier corrections too: resolve `correction_of` chains transitively to the original measurement even when the later correction appears earlier in the input file, then use only the newest terminal correction as the live event.

The output JSON at `/app/out/summary.json` must contain sorted `services`, per-metric `count`, `sum`, `min`, `max`, and `avg`, sorted source lists, and `totals` with `service_count`, `event_count`, `dropped_events`, and `suppressed_events`. Compute each metric's `avg` as `sum / count`. Each service entry should look like `{"service":"...","tier":"...","event_count":0,"sources":["..."],"metrics":{"metric_name":{"count":0,"sum":0,"min":0,"max":0,"avg":0}}}`. Only events whose normalized service is not recognized by the config count as `dropped_events` and are excluded from metrics; deduplicated records and original events superseded by corrections do not increase `dropped_events`.

After deduplication and correction replacement, recognized effective events with `value` exactly `0` are suppressed. Count each such event in `totals.suppressed_events`, but do not include it in service `event_count`, metric aggregates, source lists, or retention-window anchors. Suppressed events are recognized, so they do not count as `dropped_events`.

Apply each service's `retention_days` after deduplication, correction replacement, and zero-value suppression. For each canonical service, find the latest `occurred_at` among its recognized, non-suppressed effective events, subtract that service's `retention_days`, and keep only events whose RFC3339 timestamp is at or after that cutoff. Retention-filtered events are excluded from metrics, service event counts, and source lists, but they do not count as `dropped_events` or `suppressed_events`.
