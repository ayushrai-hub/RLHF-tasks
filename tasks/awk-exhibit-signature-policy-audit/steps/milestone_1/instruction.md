The exhibit kiosk under /app decides whether each signed image may be shown, and it's misbehaving: several images whose detached signatures are actually fine get rejected, and a retired signing key is still being trusted. The local /app/data/exhibit_signing.db is only a stale snapshot — the authoritative current state of each key lives in the kiosk's Trust Registry service — and the library that is supposed to reconcile them, /app/lib/media_sig_audit.awk, is only half-built.

Start with the catalog. Get `/app/bin/audit.sh catalog` to write /app/output/signing_catalog.json the way /app/docs/signing_policy.md and /app/config/schemas/signing_catalog.schema.json describe — every image joined with its signing key, whose current state is reconciled against the live registry, plus any policy exception. The fixed inputs, the registry endpoint, and the output paths are in /app/config/audit_contract.toml. The way the library reads the database and the registry is where the trouble starts.
