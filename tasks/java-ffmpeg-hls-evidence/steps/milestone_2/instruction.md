### Milestone 2: per-segment AES-128 decryption + audit log chain

Build on the working M1 surface. Implement `recover decrypt <segment_index>` and `recover decrypt-all`, plus the audit-chain inserts they trigger. Every call writes one row into `audit_log` with the chained `entry_hash` documented in `/app/docs/audit-chain.md`. Internet access is still disabled; no new dependencies.

For a single segment the flow is exactly: (1) look up the playlist + active key version via `/app/data/segment_index.json`; (2) re-verify `wrapped_keys.sig_hex` (the same HMAC contract M1 enforced); (3) AES-KW unwrap `wrapped_key_hex` with the 32-byte master key to recover the 16-byte content key; (4) read the ciphertext bytes from `/app/data/hls_export/segments/<NNNN>.ts.enc`, AES-128 CBC decrypt with the playlist IV, strip PKCS#7 padding, and write the plaintext to the sibling `<NNNN>.ts`; (5) append one `audit_log` row with `action=decrypt`, `target=<segment_index>`, `decision=allow`. On any failure path emit the documented error code from `error-codes.md` and append a `decision=deny` row before exiting 1. Success bodies are `{"audit_id":N,"bytes":B,"segment":I,"status":"ok"}`.

`recover decrypt-all` iterates every entry in `segment_index.json` in `segment_index` order and runs the single-segment flow once per entry, accumulating allow/deny counts. The success body is `{"allowed":A,"denied":D,"status":"ok"}` and exit is 0 iff every call succeeded. Concurrency is not required; sequential execution keeps the audit chain deterministic.

Implement the audit chain per `/app/docs/audit-chain.md`: `prev_hash` for `seq=1` is 64 zeros, otherwise the prior row's `entry_hash`; `entry_hash` is the lowercase-hex HMAC-SHA256 of `seq|ts_epoch_ms|actor|action|target|decision|prev_hash` keyed by the master key. The clock comes from `System.currentTimeMillis()` unless `RECOVERY_NOW_OVERRIDE` (unix ms) is set in the environment, in which case the override is used verbatim. The verifier sets the override so timestamps are reproducible.

Keep M1's `init` and `recover-config` working unchanged after the M2 changes; the verifier reruns both before invoking the M2 surface. The implementation lives in the same nine source files under `/app/src/com/evidence/recovery/` plus the existing helpers; do not add new packages or rename any class. Recompile via the same `javac` invocation M1 used.
