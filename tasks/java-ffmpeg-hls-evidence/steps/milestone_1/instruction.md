### Milestone 1: H2 evidence DB bootstrap, wrapped-key queries, recovery-config repair

A corrupted encrypted body-camera HLS export sits under `/app/data/hls_export/`. The Java recovery service at `/app/src/com/evidence/recovery/` is a skeleton: every method throws `UnsupportedOperationException`. Read every file under `/app/docs/` before touching code. The full task spans three milestones; this milestone bootstraps the H2 evidence database, seeds the wrapped-key rows from `/app/data/wrapped_keys.json`, and repairs the broken `recovery_config.json`. M2 and M3 do per-segment decryption and ffmpeg remux respectively.

Build the CLI into `/app/build` and provide a thin wrapper `/app/recover` so reviewers and the verifier run it as a single command. Compile with `javac -cp "/opt/jars/*" -d /app/build /app/src/com/evidence/recovery/*.java`. Make `/app/recover` an executable bash script that invokes `java -cp "/opt/jars/*:/app/build" com.evidence.recovery.RecoveryMain "$@"`. Every subcommand prints exactly one compact JSON object to stdout on success (keys ASCII-ascending) and exits 0; errors emit one compact JSON object to stderr and exit 1. See `/app/docs/API_SPEC.md`, `/app/docs/h2-schema.md`, and `/app/docs/error-codes.md` for the exact contract.

Implement two subcommands in M1. `recover init` connects to `jdbc:h2:file:/app/data/evidence` via the bundled H2 driver at `/opt/jars/h2-2.2.224.jar`, creates the four tables `playlists`, `wrapped_keys`, `audit_log`, `artifacts` exactly per `h2-schema.md`, then seeds one playlist row plus one wrapped-key row for every entry in `/app/data/wrapped_keys.json`. Re-runs are idempotent: existing rows are left untouched and `seeded_keys` reports the count of input rows considered. The success body is `{"db":"<path>","seeded_keys":N,"status":"ok"}`. `recover recover-config` reads `/app/data/recovery_config.json`, repairs the five broken fields per the table in `/app/docs/hls-recovery.md`, writes the corrected JSON back (two-space indent, keys ASCII-ascending, trailing newline), and returns `{"repaired":[<field>,...],"status":"ok"}` with the field list sorted ASCII-ascending. Each broken field has one and only one correct replacement, derived deterministically from the spec and the master-key path.

Verify the wrapped-key signature before trusting any row. The `sig_hex` column is the lowercase-hex HMAC-SHA256 of the canonical string `playlist_id|key_version|wrapped_key_hex|iv_hex` keyed by the 32-byte master key at `/opt/evidence_keys/master.key.hex` (path overridable via the `MASTER_KEY` env). `init` MUST refuse to seed any row whose signature does not verify and instead emit `{"error":"sig_mismatch","message":"..."}` on stderr with exit 1, leaving the database empty. The verifier exercises both the happy path and a tampered-row failure path.

Keep the implementation contained to the existing eleven source files under `/app/src/com/evidence/recovery/`; do not add new packages. Rebuild after every edit so `/app/build/com/evidence/recovery/*.class` is fresh. Internet access is disabled.
