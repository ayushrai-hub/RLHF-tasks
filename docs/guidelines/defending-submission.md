# Defending Your Submission

How to respond to review feedback and appeals.

## Responding

1. Read each comment fully
2. Acknowledge valid points with specifics
3. Explain reasoning if you disagree (with evidence)
4. Ask clarifying questions when feedback is unclear

## Making Changes

- Address **every** point raised
- Document changes explicitly in revision notes
- Fix only what's asked — don't rewrite unrelated code

## Disagreements

Push back respectfully with technical evidence. Escalate via Slack `#terminus-2nd-edition` if unresolved.

## Appeals

When declined unfairly: quote feedback, respond with evidence, stay professional. Final decisions are final.

## Tips

| Phase | Action |
|-------|--------|
| Before submit | `./scripts/terminus check-all`, self-review, peer glance |
| During review | Respond in 1–2 days, collaborative tone |
| If declined | Learn, salvage or restart |

Reviewers want tasks to succeed — feedback is meant to improve, not reject.
